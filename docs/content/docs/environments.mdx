title: Environments

An environment is an isolated compute configuration that defines what infrastructure your runs execute on. Environments are created and managed through the Tahuna CLI.

## Creating an environment

Initialize an environment in your project:

```bash
tahuna init .
```

This initializes the current project, writes local project state to `.tahuna/tahuna.toml`, and creates any missing project files needed for a run.

## Configuration

The local project file `.tahuna/tahuna.toml` records the paths and bindings Tahuna uses for the project:

```toml
[project]
entrypoint = "train.py"
data_dir = "data"
output_dir = "outputs"
config_file = "config.yaml"
python_project_file = "pyproject.toml"
uv_lock_file = "uv.lock"

[environment]
framework = "pt"
python_version = "3.11"
```

### Fields

| Field | Description | Example |
| --- | --- | --- |
| `entrypoint` | Training script Tahuna executes for the project | `train.py` |
| `data_dir` | Directory synced as project input data | `data` |
| `output_dir` | Directory collected for run outputs and artifacts | `outputs` |
| `config_file` | Project config file path used by your training code | `config.yaml` |
| `python_project_file` | Python project metadata used for dependency resolution | `pyproject.toml` |
| `uv_lock_file` | Lockfile used to install pinned dependencies in the runtime | `uv.lock` |
| `framework` | Detected framework key stored for the project | `pt`, `tf` |
| `python_version` | Detected Python version for the environment setup | `"3.11"` |

## Data bindings

Environments can have data bound to them. Bound data is automatically mounted when a run starts.

You can bind data via the CLI:

```bash
tahuna env data bind <environment-id> <data-id>
```

To unbind:

```bash
tahuna env data unbind <environment-id> <data-id>
```

## Deleting an environment

```bash
tahuna env rm <environment-id>
```

This permanently removes the environment, all its runs, and associated logs, metrics, and artifacts.
