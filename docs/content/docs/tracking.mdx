Tahuna provides a W&B-compatible tracking surface for training runs. Your code can use `import wandb`, `wandb.init()`, and `wandb.log()` while Tahuna captures the resulting metrics inside your Tahuna run.

## What is supported

Tahuna currently supports the compatibility flow required for a standard tracked run:

- Run initialization and bucket upsert
- Numeric metric logging
- Summary updates
- Uploads for `wandb-metadata.json`, `config.yaml`, `requirements.txt`, and `wandb-summary.json`

This is a compatibility layer for Tahuna runs, not a full clone of the W&B product surface.

## Setup

### 1. Use the normal W&B SDK in your code

```python
import wandb

run = wandb.init(
    project="mnist-demo",
    name="baseline-a100",
    config={
        "epochs": 5,
        "batch_size": 64,
        "learning_rate": 1e-3,
    },
)

for step in range(5):
    loss = 1.0 / (step + 1)
    accuracy = 0.75 + step * 0.04
    wandb.log({"loss": loss, "accuracy": accuracy}, step=step)

run.finish()
```

### 2. Let Tahuna manage the endpoint and auth

On Tahuna-managed runtime images, `WANDB_BASE_URL` is already configured to point at Tahuna's compatibility endpoint.

You usually do not need to set `WANDB_API_KEY` yourself:

- If `WANDB_BASE_URL` points to Tahuna and `WANDB_API_KEY` is unset, Tahuna injects `WANDB_API_KEY` automatically for the run.
- If you already set `WANDB_API_KEY`, Tahuna leaves your value untouched.
- If you override `WANDB_BASE_URL` to a non-Tahuna endpoint, Tahuna does not inject credentials for you.

## What Tahuna captures

Tahuna stores compatibility data for the run and mirrors logged metrics into the normal Tahuna run metrics stream.

In practice:

- Numeric metrics logged through `wandb.log()` show up in Tahuna live metrics.
- Summary updates are captured on the backend.
- Uploaded compatibility files such as `config.yaml` and `requirements.txt` are stored on the backend for the run.

## Where it shows up

After the run starts emitting metrics:

- The dashboard run detail shows the metrics in the live metrics charts.
- The CLI run views use the same underlying Tahuna metrics stream.

## Verification checklist

Use this checklist to confirm the integration is working in your environment:

1. Launch a Tahuna run with training code that calls `wandb.init()` and `wandb.log()`.
2. Confirm the run does not require a manually supplied `WANDB_API_KEY` when using Tahuna's default endpoint.
3. Open the run in the dashboard and verify that logged numeric metrics appear in the live charts.
4. Refresh the run page and confirm the metrics still appear after reload.
5. If you intentionally point `WANDB_BASE_URL` somewhere other than Tahuna, confirm Tahuna no longer auto-injects `WANDB_API_KEY`.

## Current compatibility surface

Tahuna's current implementation is built around the W&B-compatible request flow used for regular tracked runs:

- GraphQL operations for server features, run upsert, and upload URL creation
- File stream ingestion for history and summary updates
- Upload endpoints for run metadata and auxiliary config files

If your workflow depends on broader W&B product features beyond this core run-tracking path, verify them explicitly against Tahuna before depending on them.
