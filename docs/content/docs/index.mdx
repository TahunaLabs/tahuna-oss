Tahuna is a training and serving orchestration platform for teams that want full control over their Python code without taking on the infrastructure work around it. You keep your training loop and inference server. Tahuna handles code and data sync, dependency installation, run execution, model serving, metrics capture, and artifact persistence, while managed billing handles hosted compute by default.

## Why Tahuna exists

Most ML training workflows still force a bad tradeoff. You can rent raw GPU compute and manage the whole stack yourself, or you can use a managed fine-tuning API and give up control over the training loop. Tahuna sits between those two options. It is the control plane between your local project and cloud GPUs, so you can run custom training and post-training workloads without SSH, Dockerfiles, or cluster setup.

## What Tahuna does - A gentle control plane

Tahuna turns a local project into reproducible remote execution:

- You define an environment for your project.
- Tahuna syncs your code and data into pinned snapshots.
- Tahuna provisions compute, materializes the workspace, and executes training or serving commands.
- Logs, metrics, output artifacts, and serve model snapshots are captured automatically.

### Ephemeral compute 

Tahuna's runtime compute is ephemeral: runs execute on temporary GPU pods rather than long-lived machines, and persistent state is reconstructed from pinned snapshots and stored outside the pod. Transport to Tahuna services uses encrypted connections, and provider credentials are managed by Tahuna for the default cloud path.

## How syncing works

Tahuna syncs code and data incrementally rather than uploading a fresh tarball for every run. It records ordered manifests, uploads only missing content, and pins each run to exact code and data snapshots.

See [Syncing](/syncing) for the full model.

**That makes Tahuna a good fit for researchers, agent builders, and small teams who need custom workflows but do not want to spend their time on GPU operations.**

## Key Concepts

- **Environments** - Isolated compute configurations that define the framework, GPU type, GPU count, and volume size for a project.
- **Runs** - A single remote training execution of your code in a Tahuna-managed environment, with logs, metrics, and artifacts captured as the run progresses.
- **Serves** - A long-running inference deployment from a completed run artifact or storage prefix, with health checks, logs, and authenticated inference proxying.
- **Storage** - The object storage layer that holds uploaded data, pinned manifests, and run-produced artifacts.

## Quick Start

```bash
curl -fsSL https://tahuna.app/install.sh | bash
tahuna login
tahuna init .
```

Before your first paid launch, add Tahuna credits in the dashboard billing view. Then you can launch runs:

```bash
tahuna train
```

See the [Installation](/installation) and [Quickstart](/quickstart) guides for the full setup and first-run workflow.
